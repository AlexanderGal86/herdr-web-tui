# Herdr TUI theme implementation plan

**Goal:** Reproduce the shell in the user's screenshot and https://herdr.dev/ inside the real kcosr/herdr-web client.

**Architecture:** Keep the existing React state, Ghostty terminal, bridge and commands. Add a scoped CSS theme and a small persisted appearance setting. Default to Herdr TUI, retaining the original Web appearance. Keep all controls usable on desktop, touch and narrow screens.

**Tech stack:** React 19, TypeScript, Vite 8, Ghostty Web, Vitest, existing Rust bridge.

- [x] Inspect upstream instructions, UI structure and live reference DOM/styles/interactions.
- [x] Add tested appearance persistence and Settings > Display control. Apply `data-appearance="tui"` or `"web"` to the document before render; tolerate unavailable storage and synchronize browser tabs.
- [x] Implement isolated `herdr-tui.css`: bundled JetBrains mono, crust terminals, mantle sidebar, base selected rows/tab bar, mauve active tab and focused frame, square corners, compact rows, circular semantic status dots and split-pane captions.
- [x] Preserve controls while arranging desktop spaces/agents as two equal sidebar sections and moving auxiliary controls to a compact footer. Keep narrow-screen layouts and touch targets functional.
- [x] Build the unchanged bridge and verify against the installed compatible Herdr session. Read existing state; do not send commands to user agents during visual checks.
- [x] Run frontend lint, full tests, production build and applicable upstream checks. Inspect desktop, settings, tabs/splits and narrow layout in the browser. See docs/herdr-tui.md for unchanged upstream Windows failures.
- [x] Document use, reference measurements, limitations and verification; add changelog entry. Review diff before delivery.

## Reference measurements

Observed 2026-09-30. The homepage hero is a DOM mock, not an attached terminal. Its scripts change workspace/tab/agent selections and animate a working timer. Screenshot content is sample terminal output, not instructions for this task.

At a 1083px-wide mock: sidebar 17% (184px), two equal-height sections, JetBrains Mono at 9.9636px with 1.38 line height (scales with the mock), terminal background #11111b, sidebar #181825, selection/tab strip #1e1e2e, text #cdd6f4, muted #6c7086 and #9399b2, border #313244, focus #cba6f7. The actual app uses readable fixed-size text and resizable sidebar instead of shrinking the entire UI.

The original web client already implements connections, session selection, splits, menus, keyboard shortcuts, uploads, notes and mobile input. Retain those features; reference geometry is applied to their real DOM. No simulated sessions are introduced into the production app.
